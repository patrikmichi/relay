## What's new

- **`zuano sync` across coding agents.** One command writes MCP servers,
  environment, hooks, rules, commands, skills and subagents into Claude Code,
  Codex, Cursor, OpenCode, Gemini CLI, Windsurf, Cline and GitHub Copilot.
  Entries zuano writes are tracked in a hash ledger; anything you wrote
  yourself is reported as a conflict and left alone unless you pass `--force`.
  `--to`, `--from`, `--kind`, `--scope`, `--dry-run` and `--matrix` select and
  preview what changes. Edits go through a journaled transaction, so an
  interrupted write is finished or undone by `zuano recover`.
- **`zuano mcp install` and `zuano mcp remove`** register an MCP server in
  every agent. `${VAR}` references are translated to each agent's own syntax;
  an agent that cannot expand them is skipped and reported.
- **Gateway connectors:** `zuano connectors`, `zuano connect <service>` and
  connection status in `zuano services`.
- **Approvals:** `zuano approvals list|show|approve|deny|wait`, `--wait` on
  `zuano call`, and `zuano explain` names the approval a tool needs. The
  agent profile (`zuano login --agent`, `ZUANO_AGENT`) gets its own session.
  `ZUANO_AGENT` selects a profile; it is not a security boundary.
- **Skill evals:** sets and cases, `zuano skill eval`, `zuano skill compare`,
  optimization drafts and quality history, with `--fail-on-regression` for CI.
- **Skill requirements:** installing a skill checks the connectors it needs
  and offers `zuano connect` for the missing ones; `zuano skill info`.
- **Signed downloads:** catalog downloads and plugin bundles are verified
  against Ed25519 keys pinned per gateway.
- **`zuano doctor`** checks synced MCP servers, hooks, rules, commands and
  saved sync routes.
- **`--json`** on `skill install`, `skill migrate`, `agent install|migrate|
  list|diff|scan|uninstall|rollback`, `mcp install|remove` and `sync`: one JSON
  document on stdout (plan, fidelity, what was written, warnings, the error if
  it failed), with prompts and progress on stderr.
- **Saved sync routes** (`zuano sync routes`): a plain `zuano sync` follows
  them, and a route can copy rules, commands, hooks and MCP servers from one
  agent's own config to another.

## Breaking changes and migration

### Renamed to Zuano

The product is now Zuano, published by Loopmatic. This is a clean break: there
are no compatibility aliases and nothing is migrated from the old names.

- **Command and binary:** `relay` is now `zuano`. The `gw` alias is removed.
  Archives are named `zuano-<os>-<arch>`.
- **Go module:** `github.com/patrikmichi/relay` is now
  `github.com/patrikmichi/zuano`; install with
  `go install github.com/patrikmichi/zuano/cmd/zuano@latest`.
- **Packages:** the Homebrew formula is `patrikmichi/tap/zuano` and the Scoop
  manifest is `zuano` (was `relay` in both).
- **Environment variables:** `RELAY_AGENT`, `RELAY_EMAIL`, `RELAY_TIMEOUT`,
  `RELAY_API_KEY_ORIGIN` and `RELAY_CONNECT_*` are now `ZUANO_AGENT`,
  `ZUANO_EMAIL`, `ZUANO_TIMEOUT`, `ZUANO_API_KEY_ORIGIN` and
  `ZUANO_CONNECT_*`. `GATEWAY_URL` is now `ZUANO_URL` and `GATEWAY_API_KEY` is
  now `ZUANO_API_KEY`.
- **Config directory:** `~/.config/relay` is now `~/.config/zuano`, including
  `config.json`, the sync source (`sync/`), `sync-ledger.json`,
  `transactions/`, `transaction-locks/`, `session-locks/`, `marketplace/`,
  `dpop/` and `agentport-manifest.json`. The project source directory `.relay/`
  is now `.zuano/`, and the `.relay-sync` state directory is `.zuano-sync`. The
  old files are neither read nor migrated: copy what you want to keep.
- **Keychain:** the service `relay-cli` is now `zuano-cli`. Run `zuano login`
  again; entries stored under the old service are left in place and can be
  deleted from the OS keychain by hand.
- **Markers written into agent configs:** `relay-managed` markers are now
  `zuano-managed`, the MCP server `relay` is now `zuano`, the Gemini CLI hook
  name is `zuano`, and the OpenCode plugin `relay-hooks.js` is now
  `zuano-hooks.js` (export `ZuanoHooks`). Entries, blocks and files that `relay`
  wrote are no longer recognised as managed: remove them by hand.
- **Identifiers sent to the gateway:** the OAuth client `relay-cli` is now
  `zuano-cli`, the User-Agent is `zuano/<version>` and the
  `Relay-Client-Version` header is now `Zuano-Client-Version`. The gateway must
  accept the `zuano-cli` client.
- **Gateway wire names:** the signing-key route is
  `/.well-known/zuano-signing-keys` and the eval export format is
  `zuano.skill-evals/v1`.
- **No gateway is compiled in** (unchanged). Examples use
  `https://app.zuano.ai`.

### Other changes

- **Bare `zuano sync` now syncs coding agents.** It used to pull the
  Claude Code plugin marketplace. Pull the marketplace with
  `zuano sync --marketplace` (or `--dir <path>`).
- **Unattended hook and stdio writes need `--yes`.** Adding or changing a
  hook, a local MCP command, the gateway URL, or a project's rules or remote
  MCP servers asks for confirmation in a terminal. Without one, review with
  `--dry-run` and pass `--yes`.
- **Sync is refused while `ZUANO_AGENT` is set.** An agent must not widen its
  own tools or hooks. `--yes` does not override this; run the command from a
  normal shell.
- **Sessions are bound per gateway and profile.** Run `zuano login` once; a
  session saved by `relay` is not migrated. The agent profile never falls back
  to your own session: run `zuano login --agent`.
- **`zuano logout` and `zuano tokens revoke` exit non-zero** when the gateway
  did not revoke the session ("NOT revoked on gateway"). The local session is
  still removed.
- **`--fail-on-regression` exits 20** when the run scored no cases or some
  ended in an error.
- **Go 1.26 or newer is required for `go install`.** Release archives and
  package-manager installs are unaffected.
- **Local timeout flags are renamed to `--wait-timeout`.** The old names are
  gone with no alias.
- **`--arg k=v` is always a string.** It used to turn `5` into a number and
  `true` into a boolean, so an id such as `007` was sent as `7`. Use
  `--arg-json k=<json>` for a number, boolean, object or array:
  `--arg limit=5` becomes `--arg-json limit=5`.
- **`zuano authorize --scope` is now `--tool`.** `--scope` means `user` or
  `project` everywhere else. No alias.
